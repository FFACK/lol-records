# v0.3 玩家战绩助手设计与验收

## 页面与交互

沿用 Win32 外壳和 Direct2D，不增加 WebView。头部保留身份、段位和同步状态；其下为当前大区 Riot ID 搜索输入、搜索按钮及当前对局入口。搜索支持回车提交。

左栏保持近期战绩，点击行回到历史详情；右栏的历史详情和当前阵容共用玩家卡片。每行以英雄头像、昵称和唯一标识为主，辅以 KDA、补刀、经济、英雄伤害，下一层放当前段位、两项召唤师技能及基石/副系符文，底部七个装备槽。图标悬停显示名称，段位悬停显示查询时间。

历史详情按队伍分组，汇总胜负、KDA 和经济。只展示接口实际提供的数据，不模拟 WeGame 的评分、MVP/SVP 算法。段位显示的是查询时当前单双排（不可得时回退灵活排位），与比赛当时段位明确区分。

当前对局为手动快照。选人阶段仅展示 myTeam 的公开身份，不读取对手列表；不从匿名召唤师 ID 或格子 ID 反查。选人阶段不假设我方位于蓝方。进行中按 gameData.teamOne/teamTwo 展示接口公开的阵容。大厅、匹配和结算时显示对应状态，缺失技能、战绩等不补零。

## 数据、性能与缓存

玩家搜索优先 GET `/lol-summoner/v1/alias/lookup`，使用 gameName 和 tagLine；兼容查询回退必须校验返回的完整 Riot ID，避免跳转到同名玩家。所有参数按 UTF-8 字节编码，限制输入长度，不允许向提权助手传入任意 URL。

保留一次 UAC 的受限命名管道连接。固定请求帧扩为 129 字节，新增搜索、阵容及单玩家段位指令；两端校验输入。提权进程不提供通用 HTTP、文件或命令执行能力。

详情基础数据先呈现，段位作为低优先级请求补齐。查询工作线程在每个请求之间优先处理新的战绩/玩家/阵容操作，不能中断已发出的单个请求。当前选中缓存的段位一小时内复用；同进程复用已查询结果。阶段快照不持久化成已完成比赛。

旧详情以 serde 默认字段兼容；旧缓存 schema_version 为 0，连接后重新读取至版本 2。英雄/装备/技能/符文/徽章按类型和素材版本独立缓存。1147 张素材进入离线安装包，小 EXE 仍能自行下载缺失图片。大符文原图允许至 1 MiB，WIC 仅生成 32/48 像素小图供界面使用，不在启动时解码全部素材。

素材元数据：Riot Data Dragon 16.22.1 的 [summoner.json](https://ddragon.leagueoflegends.com/cdn/16.22.1/data/zh_CN/summoner.json)、[runesReforged.json](https://ddragon.leagueoflegends.com/cdn/16.22.1/data/zh_CN/runesReforged.json)；段位图为 CommunityDragon 16.22 的客户端素材。元数据固定在 `src/combat-reference.json`，不依赖运行时下载最新映射。

素材准备脚本已完成 1147 张 PNG 检查和 SHA-256 清单生成。编译及静态检查通过。真实客户端搜索、选人阶段、进行中阶段和视觉排版仍需分别验收，不能由解析测试代替；当前大区、隐私和接口限制决定实际可查范围。

安装包静默安装/卸载退出码均为 0，安装后的 EXE 哈希与便携版相同，1147/1147 张图片与素材清单匹配，已有 cache.json 哈希不变。新版启动的无障碍树确认搜索输入、搜索按钮、当前对局按钮和缓存初始化状态可见；本次客户端连接未成功，在线搜索与阵容验收尚未通过。Windows 自动化点击返回 `coordinate input geometry is unavailable`，未将此作为按钮交互通过。
