# 原生双栏 v0.2.0 验收记录

2026-11-18，Windows 10 Pro x64 10.0.19045。同机对比 v0.1.7（`e0d9f4a`）和 v0.2.0。两版用同一份独立的战绩与图片缓存快照，交替启动五次，每次关闭后再开始下一次。测试时未触发新的 LCU 同步请求。

## 性能

从启动进程计时，到 GUI 进入输入空闲、主窗口已显示句柄并能响应。两版均在进入消息循环前绑定缓存，新版还同步提交首轮绘制。这是缓存首屏的就绪代理，未逐帧测量桌面实际出图。内存于窗口就绪后约 10 秒采样。

| 指标 | v0.1.7 | v0.2.0 | 增量 |
|---|---:|---:|---:|
| EXE 大小 | 1,303,040 B，1.24 MiB | 1,401,344 B，1.34 MiB | 98,304 B |
| 窗口就绪中位值 | 220 ms | 371 ms | 151 ms |
| 窗口就绪最大值 | 254 ms | 407 ms | 153 ms |
| 10 秒工作集，中位值 | 61.23 MiB | 87.62 MiB | 26.39 MiB |
| 10 秒私有内存，中位值 | 38.83 MiB | 91.02 MiB | 52.19 MiB |

五次就绪耗时分别为 254、206、229、214、220 ms 和 371、407、395、363、367 ms。包体满足 ≤2 MiB，窗口就绪代理满足 ≤1 秒及相对基线增量 ≤200 ms。新版进程额外加载 DXGI、D3D11 和 NVIDIA 用户态驱动。该差异与采用默认 Direct2D HWND 渲染目标一致，尚未分离驱动、渲染目标和图像缓存各自的内存开销。

## 已验证

- 真实国服会话同步出两项段位和 20 场战绩，随后在同一个工具会话取得两场未缓存的标准对局。两局均有双方各五人、完整击杀字段、七个装备槽和可信本人标记。关闭工具后观察到授权工作进程退出。
- 签名版启动可加载真实旧缓存。Windows 辅助功能树暴露了原生列表及 20 行中文英雄名、胜负、KDA、模式和时间。独立空缓存目录里的窗口也能正常打开。
- 自动化样例检查了缺失或为零的统计、多队编号、标准比分完整性、空装备槽及第七槽、旧字符串缓存保留、快速 A/B/C 点选和迟到回包、窄栏装备命中，以及 96/120/144 DPI 坐标换算。
- 本机 Direct2D HWND 测试完成了 WIC 小图解码、位图上传、中文文字绘制和 EndDraw。实机缓存生成了头像和装备两个独立目录。
- 本地隔离目录里用 v0.1.7 的更新进程校验了 v0.2.0 的签名、替换和重启。故意让已签名的测试程序在就绪前退出，旧 EXE 按哈希核对成功恢复并重新打开。
- `cargo fmt --check`、`cargo test --locked` 和 `cargo clippy --locked --all-targets -- -D warnings` 通过。`scripts/release.ps1` 生成单文件 EXE 和 64 字节签名。

## 发布前仍需复核

- Windows 11 双击启动，以及 Windows 100%、125%、150% 实际缩放下的裁切、滚动、焦点和装备提示。当前仅有 DPI 换算和布局测试。
- 有数据、无数据、详情和窄窗口四张截图。窗口捕获超时，已用辅助功能树和本机数据确认部分交互，仍需视觉复核。辅助功能树中的详情面板只有原生窗格，装备提示以界面文字方式展示。
- 取消 UAC 后的界面、同一次授权后的再次同步、真实断网和 CDN 超时、实际设备目标丢失后的回退。模拟网络不可达的命令被执行环境策略拦截，空缓存启动已单独验证。
- GitHub Release 下载与线上更新全链路。当前验收仅使用本地签名产物，未创建 Release。
