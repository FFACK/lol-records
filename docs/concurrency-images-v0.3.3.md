# v0.3.3 查询并发与透明图标

## 查询改动

- 前台查询使用独立工作通道，后台段位使用 3 个工作线程。正在执行的段位 HTTP 请求不再占用前台工作线程；并发数量受限，不为每个玩家无限创建线程。
- 普通权限和提权助手均复用 LCU 会话和 HTTP 连接池，不再为每个详情/段位重复运行 PowerShell 查找进程。刷新连接时重新读取客户端信息，以支持客户端重启。
- 读取玩家战绩时，历史与段位并行请求；附加段位查询最多等待 2 秒，失败时保留历史查询结果。单玩家后台段位仍遵循原有请求超时。
- 一次 UAC 仍复用一个受限助手。管道请求增加 64 位请求 ID，回复携带相同 ID；独立读取线程分发乱序结果，写入按完整帧加锁。超时回复不会被误配给下一次请求。
- 提权助手保留父进程 PID 校验和参数校验，仅提供原有只读请求集合；不向普通进程传输认证令牌，不提供任意 URL 或执行命令接口。

## 图片改动

- 详情英雄头像 35→48 DIP，段位徽章 28→40 DIP，召唤师技能/符文 23→30 DIP，装备 27→32 DIP；列表头像 40→44 DIP。
- 移除已加载图片背后的统一实心底板，保留 PNG 的预乘 Alpha。透明符文与段位图直接叠在卡片上；素材未加载时只画占位边框。英雄和装备原图自身已有的底色保留，不进行抠图。
- 提高缓存解码尺寸：英雄 64、技能/装备/符文 48、段位 96 像素；仍按实际显示请求解码，图标和素材不额外嵌入 EXE。
- 继续使用 1200 DIP 固定主体；玩家行统一为 92 DIP，放大窗口只增加留白。图标绘制和命中区域共用尺寸与位置。

## 验证

2026-11-19：20 项测试、Clippy（拒绝警告）通过。

新增验证覆盖：3 个段位工作同时运行时前台仍可完成；真实 Windows 命名管道上传递两个并发请求并逆序回包仍正确匹配；请求帧 ID 与参数隔离及输入校验；透明 PNG 经 WIC 解码后 Alpha 为零、RGB 预乘正确。既有固定布局图标不相交、不越界测试继续通过。

上述 IPC 测试使用本机模拟回复，没有替代国服 LCU 在线验收。尚未测得真实国服查询速度提升倍数，也未完成窗口截图视觉验收。
